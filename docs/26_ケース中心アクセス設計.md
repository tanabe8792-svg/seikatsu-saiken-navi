# ケース中心アクセス設計（生活再建ナビ）

> 一般利用者向け「登録なしで使える／LINE・メールでマイページ」は維持したまま、
> **生活再建ケース（Case）** を中心に、家族・行政・社協・ボランティアが共有できる構造へ拡張する。

関連: `docs/11_CaseManagement設計書.md`（既存 CaseFile）／現状の永続化は `user_sessions`（ユーザー単位）

---

## 1. 方針の切り分け

| レイヤ | 方針 |
|--------|------|
| **一般利用者（パターン1）** | 現状維持。本人が LINE / メールでログイン → マイページ |
| **ケース実体** | 既存 `CaseFile`（`caseId` UUID）を正とする。公開用に `publicCaseId`（例: `KMT-74XQ-3L`）を併記 |
| **アクセス** | 「ユーザーが1ケース」ではなく「ケースに複数メンバー」 |
| **今すぐ実装** | 型・公開ID・回復コード・印刷用ケースカード・SQL案（土台） |
| **後続** | サーバー側 case_members / QRスキャン開封 / 行政ポータル / マルチテナント |

**維持する約束:** 登録なしでも端末内で全機能が使える。ログインは任意の継続手段。

---

## 2. データモデル（推奨）

```
auth.users（既存）
    │
    ├── user_sessions（既存・本人の端末同期用。当面残す）
    │
    └── case_members ──► cases（新・ケース本体）
                              │
                              ├── case_access_tokens（QR / 回復コード）
                              └── case_audit_log（誰が何をしたか）
```

### `cases`
| 列 | 説明 |
|----|------|
| `id` UUID PK | 内部 `caseId`（既存 `case-…` と対応） |
| `public_case_id` text UNIQUE | 紙・口頭用 `KMT-XXXX-XX` |
| `municipality_code` | 将来テナント／担当割当の軸 |
| `subject_*` | 氏名・生年月日・住所（**機微。暗号化 or 別金庫を推奨**） |
| `case_file` jsonb | 既存 `CaseFile` 互換ペイロード |
| `status` | active / closed / … |
| `created_at` / `updated_at` | |

### `case_members`
| 列 | 説明 |
|----|------|
| `case_id` | FK |
| `user_id` | nullable（紙だけの本人は未紐づけ可） |
| `role` | `owner` / `family` / `government` / `swc` / `volunteer` / `viewer` |
| `display_name` | 「息子」「市役所 ○○課」など |
| `permissions` jsonb | ロール既定の上書き（任意） |
| `invited_by` / `created_at` | |

### `case_access_tokens`
| 列 | 説明 |
|----|------|
| `case_id` | FK |
| `kind` | `qr_session` / `recovery` / `staff_temp` |
| `token_hash` | 平文は保存しない |
| `expires_at` | 一時アクセス必須 |
| `max_uses` / `use_count` | QR窓口用 |
| `created_by_role` | 監査 |

既存アプリの `CaseFile.caseId` は内部IDのまま。UI・紙には `publicCaseId` だけ出す。

## 3. 認証パターンと実装対応

| パターン | 利用者 | アクセス手段 | フェーズ |
|----------|--------|--------------|----------|
| 1 一般 | 本人 | LINE / メール → `case_members.owner` | **現行＋メンバー表接続（P1）** |
| 2 高齢者 | 本人は紙 | 公開ID + QR / 回復コード | **公開ID・カード（今）→ サーバー開封（P1）** |
| 3 行政 | 職員 | 組織アカウント → 担当ケース一覧 | **P2** |

### QR アクセス（案）
1. カードの QR = `https://…/c/{publicCaseId}?t={shortLivedToken}` またはトークン無しで窓口ログイン必須
2. 職員がログイン済みの端末でスキャン → `case_members` に一時 `viewer`/`volunteer` を付与、または `staff_temp` トークンで開く
3. **トークン無しの公開IDだけ**では機微情報を出さない（一覧・進捗の要約のみ、または窓口認証後）

### 一時・代理アクセス
- `staff_temp` / `family_invite` トークン（期限・回数・スコープ）
- 監査ログ必須（誰が・いつ・どのケースを開いたか）
- 本人確認後の再発行は `government` ロールのみ（窓口フロー）

## 4. RBAC（将来の権限マトリクス）

| 権限 \ Role | owner | family | government | swc | volunteer | viewer |
|-------------|-------|--------|------------|-----|-----------|--------|
| 閲覧（進捗・タスク） | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| プロフィール編集 | ✓ | △ | ✓ | ✓ | — | — |
| タスク完了 | ✓ | ✓ | ✓ | ✓ | △ | — |
| 支援項目更新（り災・修理等） | ✓ | — | ✓ | ✓ | — | — |
| メンバー招待 | ✓ | △ | ✓ | △ | — | — |
| ケース閉鎖 / 再発行 | ✓ | — | ✓ | — | — | — |

△ = ポリシーで制限（市町村・組織設定）。

アプリ層では `can(role, action)` を単一関数に集約し、UIとAPIの両方で使う。

---

## 5. セキュリティ

1. **公開IDは秘密ではない** — 推測耐性はあるが、認証なしでは最小情報のみ
2. **回復コードは秘密** — ハッシュ保存、印刷は一度だけ強く案内
3. **PII** — 氏名・生年月日・住所は jsonb べた書きを避け、段階的に分離・暗号化
4. **RLS** — `case_members` 経由でのみ `cases` を読める。サービスロールは監査付き Edge Function に限定
5. **QRトークン** — 短寿命・単回または回数制限。ログ必須
6. **紛失時** — 窓口で本人確認 → 旧トークン失効 → 新 `publicCaseId` or 新回復コード

## 6. マルチテナント（将来）

- 第一キー: `municipality_code`（既存 CaseFile / KB と一致）
- 第二: `organizations`（市役所・社協・ボラ団体）と `organization_members`
- 職員は「組織に所属 → 担当ケースに `government` 等で join」
- データ分離は RLS（`municipality_code IN (staff_scope)`）で開始し、必要ならスキーマ分割

MVP の知識ベース市町村マスタ（TS）はそのまま。テナント課金・契約は別レイヤ。

## 8. 相談事項への短い回答

1. **DB** — 上記 `cases` + `case_members` + `case_access_tokens`。当面 `user_sessions.case_file` と双方向同期し、切替完了後にセッションは「最後に開いた case_id」程度に縮小。
2. **QR** — 公開ID + 署名付き短命トークン。端末は職員ログイン前提が安全。
3. **一時・代理** — トークン表 + ロール付与。アカウント共有は禁止。
4. **RBAC** — ロール既定 + 任意上書き jsonb。判定は `can()` 一箇所。
5. **セキュリティ** — 公開ID≠認証、回復コードはハッシュ、RLS、監査、窓口再発行。
6. **マルチテナント** — `municipality_code` + `organizations`。KB は共有、ケースはテナント境界。

ChatGPT 等との議論後、P1 のスコープ（家族招待だけ / 窓口QRまで等）を決めれば実装に入れる。
