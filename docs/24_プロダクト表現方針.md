# 24 プロダクト表現方針

生活再建ナビの **プロダクトの芯** と **Cursor 作業時の判断基準**。  
全フェーズ共通。新機能・コピー修正・F-001 修正・A フェーズ設計時に参照する。

---

## 判断軸（固定）

```
目的：
熊本地震で被災された方が、生活再建の途中で感じる不安を少しでも減らす。

手段：
制度を代わりに判断するのではなく、
状況を整理し、次に確認することを一緒に見つける。

姿勢：
一学生が地域課題に向き合い、
利用者の声を聞きながら改善していく。
```

---

## 価値の軸（正式・詳述）

> 熊本地震で被災された方が、生活再建の過程で抱える不安や負担を少しでも減らし、安心して一歩ずつ前に進めるよう伴走する

（旧: 「次に何をすればいいか分からない人を助ける」）

---

## AI の位置づけ

「AIケースワーカー」という名称を使う場合でも、**AI が主役にならない**。

| 主役 | AI |
|------|-----|
| 被災された方 | 情報整理の補助 |
| その生活再建 | 状況把握の補助 |
| 不安を減らすこと | 見落とし防止の補助 |

- ❌ 「AIが判断しました」「AIが支援します」（AI が前面）
- ✅ 伴走・一緒に確認（被災者と生活再建が前面）

Walkthrough 観察項目: [22](./22_SurvivorWalkthrough設計書.md) § 観察項目「AIケースワーカー」

## 機能群 = 不安を減らす仕組み（ToDo アプリではない）

| レイヤ | 被災者への意味 |
|--------|---------------|
| CaseProfile | 状況理解 — 自分のことが整理されている |
| ActionQueue | 次の一歩 — 全部ではなく今の1つ |
| Evidence / DocumentRecord | 頑張ってきた記録 — 消えない |
| CaseTimeline | 前に進んできた実感 |
| Continuity | 再訪しても孤立しない |
| DecisionExplanation | なぜこの案内なのか — 信用の表側 |

## 表現方針（Cursor 作業時）

### 禁止寄り

- 「あなたが手続きをしてください」
- 「自己責任で確認してください」
- 「最終判断は自己責任でしてください」
- 「情報が変わるので自分で確認してください」
- 「期限なので急いでください」
- 「AIが判断しました」

### 推奨

- 「一緒に確認します」
- 「整理しながら進めます」
- 「大切な判断の前に最新情報も確認しましょう」
- 「分からないことも一緒に整理できます」

### 情報の責任表現（悪い例 / 良い方向）

詳細は [23 信頼形成UX設計書](./23_信頼形成UXメモ.md) § 情報の扱い方。

**悪い例:**
```
情報の正確性は保証できません。最終判断は自己責任でお願いします。
```

**良い方向:**
```
支援制度や手続きの内容は変更される場合があります。
このサービスでは公式情報を確認しながら整理のお手伝いをします。
大切な判断の際は、最新の情報をご確認ください。
```

## B フェーズ修正の軸（F-001 対応時）

Walkthrough 後の Cursor 指示は **機能追加ではない**。

| ❌ | ✅ |
|----|-----|
| 便利な機能を追加する | **不安を1つ減らすための最小修正** |

### 修正判断 — 4つの問い（必ず通す）

新しい案・F-001 修正の可否は、次の4つで判断する。  
「AIだからこうしたい」「せっかく作ったから機能追加」等の **開発者目線の暴走を防ぐ**。

| # | 問い | No なら |
|---|------|---------|
| 1 | これは被災者の **不安を減らす** か？ | 対象外 or P3 |
| 2 | **迷いや負担を減らす** か？ | 同上 |
| 3 | **信頼につながる** か？ | 同上 |
| 4 | **開発者側の都合** になっていないか？ | 触らない |

4つすべて Yes に近いものだけ P1/P2 として最小 diff で対応する。

### B と A の境界（混ぜない）

| B の範囲（体験・伴走） | A の範囲（信頼形成） |
|----------------------|---------------------|
| ボタン位置が分からない | 誰が作っているのか気になる |
| 表現が冷たい | 情報源への不安 |
| 情報量が多い | 応援したい |
| 次に何を押すか迷う | 意見を届けたい |

Walkthrough 後の F-001 仕分け: [22](./22_SurvivorWalkthrough設計書.md)

コピー変更・表示の微調整を優先。ロジック変更は原則しない。

### B の評価基準（機能数ではない）

| # | 基準 |
|---|------|
| ① | 迷わないか |
| ② | 不安が減るか |
| ③ | 次の一歩が分かるか |
| ④ | 前に進んでいる実感があるか |

### プロダクトの方向

「便利な災害情報サイト」ではなく、

**被災後の混乱した状況で、一緒に整理してくれる伴走者**

Walkthrough では機能確認より **一人で使った時に孤独感や不安が増えないか** を見る。
