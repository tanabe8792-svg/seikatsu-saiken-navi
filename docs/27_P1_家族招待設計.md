## データモデル

```
cases
  ├── case_members (user_id, role, access_level)
  ├── case_invites (invite_code, access_level, expires)
  └── case_audit_log
```

- `access_level`: `view` | `edit`（P1 の実務権限）
- `role`: `owner` | `family` | …（将来の細分化）
- `case_status`: `self_managing` | `family_support` | `gov_support` | `completed`
- `assigned_organization` / `assigned_user` / `updated_by`: 列のみ（P3）

既存 `user_sessions` は本人端末の同期用として残す。共有の正は `cases.case_file`。

---

## 招待フロー

1. 所有者がログイン
2. マイページ →「家族・代理人を招待」
3. `publish_owned_case` でケースをクラウドへ
4. `create_family_invite` でコード＋リンク発行
5. 代理人が `/invite/{code}` を開き、**自分の** LINE/メールでログイン
6. `accept_family_invite` で `case_members` に紐付け、ケース内容を端末へ読込

---

## P2 QR（方針どおり）

`/c/{publicCaseId}` は番号の入口のみ。

1. QR読込 → ケース番号表示  
2. 未ログイン → ログイン要求  
3. ログイン済 → `get_case_by_public_id` で権限確認  
4. メンバーのみケース表示  

QR単体では機微情報を出さない。

## セットアップ（必須）

Supabase SQL Editor で:

1. 既存どおり `supabase-schema.sql` / `supabase-schema-auth-extension.sql`
2. **`database/supabase-schema-cases.sql` を実行**（P1 RPC 含む）

未実行でも一般利用は動く。共有ボタンは準備中メッセージになる。
