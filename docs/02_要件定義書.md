## 1. サービス概要

### 1.1 サービス名

**生活再建ナビ（仮）**

### 1.2 目的

災害発生後、被災者が**自分に必要な支援・手続き・生活再建への道筋**を迷わず把握できるサービスを提供する。

### 1.3 サービスコンセプト

被災直後から生活再建が安定するまで、被災者の状況（被災の種類、住居の状態、家族構成、雇用状況など）に応じて、取るべきアクションを整理し、次に何をすればよいかをわかりやすく提示する「生活再建のナビゲーター」である。

### 1.4 提供価値

| 価値 | 説明 |
|------|------|
| 見通しの提供 | 生活再建に必要な手続き・支援を一覧化し、全体像を把握できる |
| 優先順位の明確化 | 今すぐ必要な対応と、後からでよい対応を区別できる |
| 情報の集約 | 分散している行政情報・支援制度・手続き情報への入口を一つにまとめる |
| 不安の軽減 | 「自分は何をすればいいのかわからない」という状態から、次の一歩が見える状態へ |

### 1.5 サービスの位置付け

- 被災者向けの**情報整理・ナビゲーションサービス**である
- 行政の公式窓口や支援機関の**代替ではない**
- 専門家（行政書士など）による**個別相談・代理業務の代替ではない**
- 被災者が自力で情報を得て行動する際の**補助輪**として機能する

## 2. 解決する課題

### 2.1 被災者が直面する課題

| 課題 | 具体例 |
|------|--------|
| 情報過多・情報分散 | 自治体、国、保険会社、金融機関、NPO など情報源がバラバラで、どこを見ればよいかわからない |
| 優先順位がわからない | 避難所の確保、罹災証明、保険請求、住居確保など、同時並行で必要なことが多く、何から手をつけるべきか判断できない |
| 自分ごと化の困難 | 「自分の状況に該当する支援は何か」を自力で判断するのが難しい |
| 期限・期限付き手続きの見落とし | 申請期限のある支援制度や手続きを知らずに期限を過ぎてしまう |
| 精神的・身体的負担 | 被災直後は心身ともに余裕がなく、複雑な情報整理が負担になる |
| デジタル格差 | 高齢者やスマートフォンに不慣れな方は、オンライン情報の取得自体がハードルになる |

### 2.2 支援者が直面する課題

| 課題 | 具体例 |
|------|--------|
| 正確な情報提供の困難 | 家族・知人が支援したいが、最新の制度情報や手続き方法を把握していない |
| 支援内容のすり合わせ不足 | 被災者本人と支援者で「何を優先すべきか」の認識がずれる |

### 2.3 本サービスが解決すること／解決しないこと

**解決すること**

- 被災状況に応じた「次にやること」の提示
- 支援制度・手続き情報への整理された入口の提供
- 生活再建プロセス全体の見通しの提供

**解決しないこと（スコープ外）**

- 個別案件に対する法的判断・代理手続き（→ 専門家連携の領域）
- 被災者の代わりによる行政・金融機関との交渉
- 物的支援（物資・資金）の直接提供
- 被災地のリアルタイム被害状況の公式情報提供（→ 自治体・メディアの領域）

## 3. 想定ユーザー

### 3.1 プライマリユーザー

| ユーザー | 説明 | 主なニーズ |
|----------|------|-----------|
| 被災者本人 | 地震・水害・火災などにより生活基盤に影響を受けた方 | 自分に必要な支援・手続きを知りたい。何から始めればよいか知りたい |
| 被災者の家族・親族 | 遠方にいる家族など、被災者を支援する立場の方 | 被災者に何を手伝えばよいか、正確な情報を得たい |

### 3.2 セカンダリユーザー

| ユーザー | 説明 | 主なニーズ |
|----------|------|-----------|
| 地域の支援者 | ボランティア、自治会、近隣住民など | 被災者への情報提供・支援のたたき台が欲しい |
| 支援 NPO・市民団体 | 被災者支援活動を行う団体 | 被災者に案内できる信頼性のある情報源が欲しい |

### 3.3 将来の検討対象（MVP 外）

| ユーザー | 説明 |
|----------|------|
| 自治体職員 | 被災者への情報提供ツールとしての活用 |
| 社会福祉協議会・支援機関 | ケース支援時の情報参照 |
| 専門家（行政書士等） | 被災者からの相談前の情報整理ツールとしての紹介 |

### 3.4 ユーザー属性の想定

- 年齢層：幅広い（高齢者を含む）
- デジタルリテラシー：様々（スマートフォンは使えるが複雑な Web 操作は苦手な層を想定）
- 被災の種類：地震、水害、火災、土砂災害など
- 被災規模：個別被災（自宅のみ）〜 広域災害

## 4. 利用シーン

### 4.1 シーン一覧

| # | シーン | タイミング | ユーザーの状態 | サービスが提供すること |
|---|--------|-----------|---------------|---------------------|
| 1 | 被災直後 | 発災〜72時間 | 混乱・不安・情報不足 | 最優先で行うべきこと（安全確保、避難、連絡）の提示 |
| 2 | 避難生活開始 | 被災後 3日〜2週間 | 生活の足場がなく、手続きの必要性を認識し始める | 罹災証明、避難所情報、生活必需品に関する手続きの案内 |
| 3 | 生活再建の計画 | 被災後 2週間〜3ヶ月 | 住居・仕事・学校など中長期の再建を考え始める | 住居確保、保険請求、支援制度申請などの道筋の提示 |
| 4 | 手続きの実行 | 被災後 1ヶ月〜 | 個別の手続きに取り組む段階 | 各手続きの概要、必要書類、申請先、期限の案内 |
| 5 | 支援者による情報共有 | 被災者と支援者が離れている場合 | 支援者が遠隔で支援したい | 被災者の状況に応じたチェックリストの共有・確認 |
| 6 | 専門家相談の判断 | 手続きが複雑化した場合 | 自力では判断・対応が難しいと感じる | 専門家に相談すべきケースの案内、連携先の紹介 |

### 4.2 代表的なユーザージャーニー（例：地震で自宅が半壊）

1. 被災直後：スマートフォンで「生活再建ナビ」を開き、状況（半壊・自宅に住めない）を選択
2. サービスが「今すぐやること」「1週間以内にやること」を提示
3. 罹災証明の取得方法、仮設住宅の申請方法などを順番に確認
4. 支援制度の一覧から、自分に該当しそうなものをチェック
5. 複雑な手続き（例：火災保険と公的支援の併用）で迷った場合、専門家相談の案内を確認

## 5. 基本方針

### 5.1 プロダクト方針

| 方針 | 内容 |
|------|------|
| 被災者ファースト | 被災直後の心身状態を前提に、シンプルで負担の少ない UI・情報設計とする |
| 状況に応じた提示 | 一律の情報羅列ではなく、被災状況に応じて必要な情報だけを提示する |
| 公式情報の尊重 | 行政・公的機関の情報を正とし、出典を明示する |
| 過度な期待を持たせない | 「確実に支援が受けられる」などの断定表現を避け、制度の概要と確認先を示す |
| 専門家領域との線引き | 法的判断・代理手続きは専門家の領域であることを明示する |

### 5.2 情報の取り扱い方針

- 掲載情報は**自治体・国・公的機関の公式情報**をベースとする
- 情報の出典・更新日を明示する
- 制度内容は変更される可能性があるため、「最新情報は各機関の公式サイトで確認してください」と案内する
- 被災地・被災種別によって適用される制度が異なることを明示する

### 5.3 デザイン・UX 方針

- 被災直後でも操作できる**シンプルな導線**を優先する
- 専門用語は避け、平易な言葉で説明する（必要に応じて用語解説を付ける）
- 文字サイズ・コントラストなど、アクセシビリティを考慮する
- 将来的なオフライン対応・低帯域対応を視野に入れる

### 5.4 運営方針

- 非営利または社会的目的を主目的とした運営を想定する
- 寄付による運営費の賄いを検討する（詳細は「10. 運営・寄付・お問い合わせ機能」参照）
- 被災者から個人情報を過剰に収集しない

## 6. MVP（最初に作る機能）

MVP では、被災者が**状況を入力し、自分に必要なアクションの一覧を得られる**最小限の体験を実現する。

### 6.1 MVP のゴール

> 被災者が自分の状況を選択すると、「今すぐやること」「近日中にやること」「後で確認すること」が整理されて表示される。

### 6.2 MVP 機能一覧

| # | 機能 | 概要 | 優先度 |
|---|------|------|--------|
| 1 | 状況入力（簡易診断） | 被災の種類、住居の状態、家族構成などを選択式で入力 | 必須 |
| 2 | アクションリスト表示 | 入力状況に応じた「やることリスト」を優先度付きで表示 | 必須 |
| 3 | 各アクションの詳細説明 | 手続きの概要、必要書類、申請先、参考リンクを表示 | 必須 |
| 4 | チェックリスト機能 | 完了したアクションにチェックを入れて進捗を管理 | 必須 |
| 5 | 支援制度の概要一覧 | 主要な支援制度の概要と該当可能性の目安を表示 | 必須 |
| 6 | 静的コンテンツ管理 | 手続き・支援制度の情報を運営側で更新・管理 | 必須 |
| 7 | 運営情報ページ | サービス概要、免責事項、プライバシーポリシー、お問い合わせ先 | 必須 |
| 8 | 寄付ページ | 運営支援のための寄付案内（外部決済サービス連携） | 必須 |

### 6.3 MVP に含めないもの

| 機能 | 理由 |
|------|------|
| ユーザーアカウント・ログイン | 個人情報収集を最小化するため、MVP ではローカル保存または匿名利用を想定 |
| 被災地のリアルタイム情報連携 | 情報源の整備・更新体制が必要なため後続フェーズ |
| 専門家とのマッチング・予約 | 連携体制構築が必要なため後続フェーズ |
| 多言語対応 | MVP 後に段階的に対応 |
| 自治体向け管理画面 | 被災者向け体験の確立を優先 |

### 6.4 MVP の成功指標（案）

| 指標 | 目標（案） |
|------|-----------|
| 状況入力完了率 | 入力開始者の 70% 以上が完了 |
| アクション詳細の閲覧 | 表示されたアクションの 50% 以上で詳細を閲覧 |
| チェックリスト利用率 | 利用者の 30% 以上が 1 件以上チェック |
| 再訪率 | 7 日以内に 20% 以上が再訪 |

## 7. 将来的な機能

MVP 以降、段階的に検討・実装する機能。

### 7.1 機能拡張

| 機能 | 概要 | フェーズ |
|------|------|---------|
| 被災地・自治体別情報 | 被災地を選択すると、該当自治体の支援情報を表示 | Phase 2 |
| 期限リマインダー | 申請期限のある手続きの通知（メール・プッシュ等） | Phase 2 |
| 進捗の保存・共有 | アカウントまたは共有リンクで進捗を保存・家族と共有 | Phase 2 |
| 書類準備ガイド | 必要書類のテンプレート・記入例の提供 | Phase 2 |
| よくある質問（FAQ） | 被災種別・手続き別の Q&A | Phase 2 |
| オフライン対応 | 主要コンテンツのオフライン閲覧 | Phase 3 |
| 多言語対応 | 外国籍被災者向け（英語、中国語、ポルトガル語等） | Phase 3 |
| 音声読み上げ | 高齢者・視覚障害者向け | Phase 3 |

### 7.2 連携・エコシステム

| 機能 | 概要 | フェーズ |
|------|------|---------|
| 専門家相談の案内・予約 | 行政書士等への相談導線（詳細は「11. 専門家連携」参照） | Phase 2 |
| 支援 NPO・ボランティア情報 | 地域の支援団体情報の掲載 | Phase 2 |
| 自治体・支援機関向け機能 | 情報更新・被災者向け告知の連携 | Phase 3 |

### 7.3 データ・分析（匿名化前提）

| 機能 | 概要 |
|------|------|
| 匿名化された利用傾向分析 | どの手続き・支援情報がよく閲覧されるかを把握し、コンテンツ改善に活用 |
| 被災パターン別の改善 | 状況入力パターンごとに不足している情報を特定 |

## 8. 非機能要件

### 8.1 可用性・信頼性

| 要件 | 内容 |
|------|------|
| 可用性 | 災害時の利用を想定し、高い可用性を目指す（具体的 SLA はインフラ選定時に決定） |
| 耐障害性 | 単一障害点を避け、冗長構成を検討する |
| スケーラビリティ | 広域災害時のアクセス急増に耐えうる構成を検討する |

### 8.2 性能

| 要件 | 内容 |
|------|------|
| ページ表示速度 | 被災地の通信環境が不安定な場合を想定し、軽量・高速な表示を優先 |
| 初回表示 | 主要ページは 3 秒以内の表示を目標（低帯域環境は別途検討） |

### 8.3 セキュリティ

| 要件 | 内容 |
|------|------|
| 通信の暗号化 | HTTPS 必須 |
| 個人情報の最小化 | 必要最小限の情報のみ収集 |
| 脆弱性対策 | 定期的なセキュリティ更新・監査 |

### 8.4 アクセシビリティ

| 要件 | 内容 |
|------|------|
| WCAG 準拠 | WCAG 2.1 レベル AA を目標 |
| 文字サイズ | 拡大可能な設計 |
| 色のコントラスト | 十分なコントラスト比を確保 |
| キーボード操作 | 主要機能はキーボードのみでも操作可能 |

### 8.5 保守性

| 要件 | 内容 |
|------|------|
| コンテンツ更新 | 運営者が手続き・支援制度情報を非エンジニアでも更新できる仕組み |
| 情報の陳腐化防止 | 更新日・確認日の管理、定期レビューの仕組み |

### 8.6 対応環境

| 要件 | 内容 |
|------|------|
| デバイス | スマートフォン優先、タブレット・PC にも対応 |
| ブラウザ | 主要モダンブラウザの最新 2 バージョン |
| ネットワーク | 低帯域環境でも基本機能が利用可能であること（将来的対応含む） |

## 9. 個人情報保護方針

### 9.1 基本方針

被災者のプライバシーを最優先とし、**個人情報の収集を必要最小限**にとどめる。

### 9.2 MVP での個人情報の取り扱い

| 項目 | 方針 |
|------|------|
| アカウント登録 | MVP では不要（匿名利用を基本とする） |
| 状況入力データ | 被災状況の選択肢（住居状態、家族構成など）は個人を特定しない範囲の情報とする |
| チェックリスト進捗 | ブラウザのローカルストレージに保存（サーバー送信なし）を MVP の基本方針とする |
| ログ・分析 | 個人を特定できない匿名化された利用統計のみ収集 |

### 9.3 将来機能追加時の方針

| 機能 | 個人情報の取り扱い |
|------|-------------------|
| アカウント・進捗保存 | 利用目的を明示し、同意を得た上で必要最小限の情報を収集 |
| 期限リマインダー | メールアドレス等の連絡先は明示的な同意とともに取得 |
| 専門家相談予約 | 相談に必要な情報のみ、専門家への情報提供範囲を明示した上で取得 |

### 9.4 プライバシーポリシー

- サービス公開前にプライバシーポリシーを策定・公開する
- 収集する情報、利用目的、第三者提供の有無、保管期間、問い合わせ先を明記する
- 個人情報保護法および関連法令を遵守する

### 9.5 センシティブ情報への配慮

- 被災に関する情報はセンシティブな個人情報に該当しうるため、特に慎重に扱う
- 被災の詳細（具体的な被害内容、所得、借入状況など）は MVP では収集しない
- 専門家連携時の情報共有範囲は被災者本人の同意を前提とする

## 10. 運営・寄付・お問い合わせ機能

### 10.1 運営体制（想定）

| 項目 | 内容 |
|------|------|
| 運営主体 | 非営利法人または社会的目的を掲げた組織での運営を想定 |
| 運営内容 | コンテンツの更新・メンテナンス、お問い合わせ対応、寄付管理 |
| 情報更新 | 被災関連制度の変更に追随し、定期的にコンテンツをレビュー |

### 10.2 運営情報ページ（必須）

サービス内に以下のページを設ける。

| ページ | 内容 |
|--------|------|
| サービス概要 | 本サービスの目的・提供価値・利用上の注意 |
| 免責事項 | 情報の正確性、支援の受給を保証しないこと等 |
| プライバシーポリシー | 個人情報の取り扱い |
| 利用規約 | サービスの利用条件 |
| 運営者情報 | 運営主体の名称・連絡先 |
| お問い合わせ | 問い合わせフォームまたはメールアドレス |

### 10.3 寄付機能

| 項目 | 内容 |
|------|------|
| 目的 | サーバー費用、コンテンツ更新、運営人件費などの運営費用の賄い |
| 方式 | 外部決済サービス（例：Stripe、PayPal、国内決済サービス等）との連携 |
| 表示 | 寄付ページに運営目的・使途の透明性を明示 |
| 領収書 | 税制上の扱いに応じた領収書発行の可否を運営主体の法人格に合わせて検討 |
| MVP での位置付け | 寄付案内ページの設置（決済連携は MVP に含める） |

### 10.4 お問い合わせ機能

| 項目 | 内容 |
|------|------|
| 受付方法 | メールフォームまたはメールアドレス（MVP） |
| 対応内容 | サービスの使い方、情報の誤り指摘、改善提案 |
| 対応しない内容 | 個別の被災相談、法的助言、手続きの代行 |
| 返信目安 | 通常 3〜5 営業日以内（災害時は別途告知） |

### 10.5 免責事項（要点）

- 掲載情報は参考情報であり、最新・正確性を保証するものではない
- 支援の受給・手続きの成功を保証するものではない
- 個別の判断が必要な場合は専門家または関係機関への確認を促す
- 被災者の状況により適用されない制度・手続きがある

## 11. 行政書士など専門家連携の位置付け

### 11.1 基本方針

専門家（行政書士、司法書士、社会保険労務士、弁護士等）は、本サービスの**補完的存在**として位置付ける。本サービスは情報整理・ナビゲーションに徹し、個別案件への法的判断・代理手続きは専門家の領域とする。

### 11.2 本サービスと専門家の役割分担

| 領域 | 本サービス | 専門家 |
|------|-----------|--------|
| 手続きの全体像の提示 | ○ | — |
| 支援制度の概要説明 | ○ | — |
| 個別案件への適用判断 | △（該当可能性の目安のみ） | ○ |
| 書類作成・提出代行 | — | ○ |
| 保険会社・行政との交渉 | — | ○ |
| 複雑な権利関係の整理 | — | ○ |

### 11.3 専門家連携の目的

| 目的 | 説明 |
|------|------|
| 適切なタイミングでの相談誘導 | 自力では対応が難しいケースで、専門家への相談を促す |
| 被災者の負担軽減 | 情報整理は本サービス、個別対応は専門家、という分担 |
| 誤った自己判断の防止 | 複雑な手続きで専門家不要と誤判断することを防ぐ |

### 11.4 専門家相談を促すケース（例）

- 火災保険と公的支援の併用・調整が必要な場合
- 相続・名義変更が絡む場合
- 複数の支援制度の優先順位・選択が不明な場合
- 行政・保険会社との交渉が必要な場合
- 被災証明の内容に異議がある場合

### 11.5 MVP での位置付け

| 項目 | MVP での対応 |
|------|-------------|
| 専門家相談の案内文 | 該当ケースで「専門家への相談を検討してください」と表示 |
| 専門家リスト・紹介 | MVP では静的な案内のみ（連携・予約機能は Phase 2 以降） |
| 料金・報酬 | 本サービスは専門家の報酬に関与しない。直接契約は被災者と専門家間 |

### 11.6 将来的な連携形態（Phase 2 以降）

| 形態 | 概要 |
|------|------|
| 相談窓口の紹介 | 被災者支援実績のある専門家・事務所のリスト掲載 |
| オンライン相談予約 | 専門家との初回相談予約機能（外部サービス連携も検討） |
| 情報共有（同意ベース） | 被災者が同意した範囲で、本サービス上の進捗情報を専門家と共有 |
| 専門家向けダッシュボード | 被災者の状況整理状況を専門家が確認（被災者同意必須） |

### 11.7 連携上の注意事項

- 本サービスは専門家の紹介・マッチングにおいて**中立性**を保つ
- 特定の専門家・事務所への誘導を行う場合は、選定基準を公開する
- 専門家への紹介料・手数料の有無と、そのサービス上での表示方法を明確にする
- 被災者に対し、専門家利用は任意であることを明示する
