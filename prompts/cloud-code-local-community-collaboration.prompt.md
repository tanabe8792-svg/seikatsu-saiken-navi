# Cloud Code 用プロンプト：プロジェクト提案書（教員レビュー用）

以下を Cloud Code（または同等の AI）に **そのまま貼り付けて** 実行してください。
出力は **コードではなく**、大学教員（地域連携に詳しい方）が **読んで概要を把握するためのプロジェクト提案書** です。

※ 教員への「協力のお願い」文ではありません。教員が書いた提案でもありません。

---

## 貼り付け用プロンプト（ここから）

あなたは、被災者支援 Web サービス「熊本 生活再建ナビ」の **プロジェクト提案書** を書くアシスタントです。

### 読者

- 大学教員（地域社会・地域連携に関心がある方）
- **役割**: 提案書を読み、プロジェクトの輪郭・意義・限界を理解する。**本文では教員に手を貸してほしいとは書かない**

### プロジェクトの事実（提案書に盛り込む材料）

- **名称**: 熊本 生活再建ナビ
- **URL**: https://seikatsu-saiken-navi.vercel.app/
- **きっかけ**: 被災地ボランティア等で「この先、何から手をつければいいか分からない」という声を聞いた経験
- **目的**: 令和8年熊本地震の被災者が、やること・手順・公式リンクを **一人で抱え込まず** 整理できる無料 Web アプリ
- **位置づけ**:
  - 行政の公式サービス **ではない**
  - 市町村と連携しておらず、画面を見せても窓口手続きは自動で進まない
  - 公式情報を入口に、被災者自身が進められるよう **伴走する** 民間の個人プロジェクト
- **主な内容（概要）**:
  - 状況に応じた「やること」一覧（罹災証明、保険、給水、事業再建など）
  - 手順 → 準備 → 申請、の順で読めるガイド
  - 熊本県内の自治体別申請案内（マイナポータル等へのリンク）
  - 進捗・メモ・写真は **主に端末内** に保存（登録不要でも利用可）
  - 長時間作業向けの休憩リマインド（約30分）
- **開発体制**: 熊本学園大学大学院 会計専門職研究科・田辺 優が個人で開発・更新。**ベータ段階**
- **地域との関係（叙述用）**: 被災者と地域支援の **間** に立つ「整理の道具」として設計。町村や NPO の仕事を置き換えるものではない
- **今後の取り組み（叙述用）**: 種類の細かい分類は決めず、**本サイトの改善** を継続する（使いやすさ、案内の正確さ、安心して使える仕組みなど）

### 個人情報・情報の扱い（提案書で **必ず** 書く。事実に沿い、誇張しない）

以下を、やさしい日本語で **独立の節** として整理すること。

1. **基本方針**
   - 被害の状況や手続きの進み具合は **利用者本人のもの**。運営者が一覧で見られる仕組みには **しない** 設計を優先している
   - 「開発者だけが内容を見られる」状態を **避ける** ことを意図している（被災者が不安に感じやすい点）

2. **登録なしで使う場合（標準）**
   - やること・進捗・メモは **お使いの端末（ブラウザ）内** に保存
   - **サーバーへ自動送信しない**（運営のサーバーに上がらない）
   - 被害写真も **端末内（ブラウザの保存領域）** に残し、**自動ではサーバーに送らない**

3. **マイページ登録（任意）**
   - 別端末から続きを再開したい人向け。**登録しなくても使える**
   - 登録時の保存・通信は **HTTPS（暗号化通信）**
   - データベース側では **本人以外が読めない制限**（行レベルセキュリティ）を設け、運営用の「全員分を見る画面」は **作っていない**

4. **例外（利用者が選んだときだけ）**
   - **AI相談** を使ったときだけ、入力内容が通信される。使わなければ送られない
   - **改善の声** を送ったときだけ、書いた内容が運営に届く（任意）

5. **個人開発への不安への配慮（事実ベースで1〜2文）**
   - 開発・更新は個人だが、**被害内容を運営者だけが覗ける構造にしない** ことを設計の中心に置いている
   - 開発者名・所属はサイト内（「このサービスについて」）で明示している
   - ベータ段階であり、制度や案内の更新は続く。大切な判断は必ず公式窓口・専門家の確認を促す

6. **書かないこと**
   - 「すべて暗号化されている」「運営者は絶対に見られない」など、技術的に言い切れない表現
   - 行政や大学の監査済みのような誤解を招く表現

### 出力してほしいもの

**プロジェクト提案書** 1本（日本語）。次を満たすこと。

1. **文体**: 第三者的な提案書。メールの「お願い」調にしない。「〜していただけますか」「ご協力お願いします」は **書かない**
2. **長さ**: A4 1.5〜2 ページ相当（1200〜1800字目安）。箇条書きを適宜使う
3. **構成**（この順）:
   - **1. 背景と課題**（被災直後〜生活再建期に何が起きやすいか）
   - **2. プロジェクト概要**（名称・URL・一行説明）
   - **3. 対象者と提供価値**（誰の、どんな困りに応えるか）
   - **4. 主な機能と利用の流れ**（4〜6行程度）
   - **5. 地域社会との接点**（地域連携の文脈での位置づけ。替わりではない、という限界も1文）
   - **6. 個人情報と情報の扱い**（上記「個人情報・情報の扱い」の材料を反映。**この節を省略しない**）
   - **7. 限界と免責**（非行政、情報の鮮度、専門判断の代替ではない）
   - **8. 現状と今後**（ベータ、**本サイトの改善** を継続する旨。協力要請は書かない）
4. **含めないこと**:
   - コード、API、技術スタックの詳細
   - 大学・行政の **公式承認があるかのような表現**
   - 教員・学生への **参加依頼・ボランティア募集・面談のお願い**
   - 「先生が書いた提案」という体裁
   - サイト内の「改善の足跡」など、教員向け提案書に **不要な UI 細部**（端末表示の説明など）
5. **トーン**: やさしい日本語。被災者の尊厳を損なわない。誇大広告にしない

### 出力形式

- タイトル（1行）
- 提案書本文
- 末尾に **「提案書の要点（3行）」** のみ（教員がざっと把握する用。質問形式にしない）

以上に従い、提案書のみ出力してください。解説や前置きは不要です。
